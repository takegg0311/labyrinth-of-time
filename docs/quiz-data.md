# 出題データ

問題文と正解は `questions.csv` で管理し、VOICEPEAK の出力ファイルは
**リネームせず**バッチ（日付）フォルダにそのまま置く。

**出題データはリポジトリに含まれていない**（`.gitignore` で除外）。
各自でローカルに配置する。

データ形式のサンプルとして、`questions_example.csv` と対応する 1 問分の
音声（`20260820/0-20260820.wav` / `.txt`）のみ追跡している。

```bash
cp quiz_data/questions_example.csv quiz_data/questions.csv
```

ただしサンプルは 1 問しかない。**1 ゲームには 12 問が要る**ので、
これだけでは起動しない（[出題候補が足りない場合](#出題候補が足りない場合)）。

## ディレクトリ

```
quiz_data/
├── questions_example.csv   ← サンプル（追跡対象）
├── questions.csv           ← 実データ（各自で用意）
├── 20260820/          ← サンプルバッチ
│   └── 0-20260820.wav / .txt
└── 20260821/          ← バッチ = VOICEPEAK プロジェクト 1 つ
    ├── 00-20260821.wav / .txt
    ├── 01-20260821.wav / .txt
    ├── ...
    ├── 11-20260821.wav / .txt
    ├── 20260821.txt   ← 使用しない（VOICEPEAK の全体出力）
    ├── 20260821.lab   ← 使用しない
    └── 20260821.vpp   ← 使用しない（VOICEPEAK プロジェクト）
```

## `questions.csv`

5 列で書く。

```csv
batch,seq,text,answer,alt_answers
20260820,0,日本で一番高い山は富士山ですが、世界で一番高い山はどこ？,エベレスト,
20260821,0,大蛇を意味する名を持つプログラミング言語は何でしょう？,Python,パイソン|ニシキヘビ
```

| 列 | 内容 |
| --- | --- |
| `batch` | バッチ名（`YYYYMMDD`）。`quiz_data/{batch}/` に対応 |
| `seq` | VOICEPEAK が出力した連番（0 起点）。`{seq}-{batch}.wav` などに対応。**整数で書く**（`0` でも `00` でも同じ） |
| `text` | 問題文。**改行を含めない**（1 問 1 ブロック） |
| `answer` | 正解 |
| `alt_answers` | 別解。`\|` 区切りで複数指定可。無ければ空 |

VOICEPEAK は連番を 0 起点でしか振れず接頭語も付けられないため、
バッチフォルダと連番の組で一意性を与えている。

ファイル名が `{seq}-{batch}` となっているのは、VOICEPEAK が連番だけの出力を
許さず接尾語が必須のため。接尾語にはバッチ名（日付）をそのまま指定する。
フォルダ名と接尾語が一致するので、別の日のファイルを取り違えて置いた場合に
参照先が見つからず検出できる。

### 別解の書きかた

回答は音声入力なので、**読みの揺れを別解に入れておく**とよい。

正誤判定は正規化した上での部分一致で行う。全角/半角・大文字小文字・
空白・中黒・長音は吸収するが、**ひらがなとカタカナは別の語として扱う**。
「伊藤博文」に対し「いとうひろぶみ」と発声された場合は別解が要る。

```csv
20260821,3,日本の初代内閣総理大臣は誰？,伊藤博文,いとうひろぶみ|イトウヒロブミ
```

文末表現は吸収されるので、別解に入れる必要はない
（「エベレストです」は「エベレスト」に一致する）。

## 音声ファイル

1 問につき `.wav` と `.txt` の 2 点が要る。

| `.wav` / `.txt` | 扱い |
| --- | --- |
| 2 つとも揃っている | 出題候補 |
| 一部だけある | **エラー**。理由を表示して起動が止まる |
| 2 つとも無い | **エラー**。同上 |

音声の再生が出題の前提なので、音声なしの問題は置けない。

`.lab`（音素タイミング）は使わない。読み上げに同期した 1 文字ずつの
文字送りをしないため。置いてあっても無視する。

`.txt` は CSV の `text` 列との突合に使う。中身が食い違っていると
起動時にエラーになるので、**問題と音声の取り違えをここで検出できる**。

### 5 秒を超える音声

1 問あたりのスロットは 5 秒しかない。これを超える音声は次の問題の
読み上げに食い込むため、**出題候補から外して警告を出す**。起動は止まらない。

```
WARNING: 5 行目 (20260821/3): 20260821/03-20260821.wav が 6.20 秒あり、スロット長 5 秒を超えるため出題候補から外しました。
```

問題文を短くして作り直す。読み上げ速度にもよるが、5 秒に収まるのは
おおむね 30 文字程度まで（VOICEPEAK の標準速度で 6〜8 文字/秒）。
実際の長さは出力してから警告の有無で確かめるのが確実である。

### 出題候補が足りない場合

除外の結果、出題候補が 12 問に満たない場合は**エラーで起動が止まる**。

```
出題可能な問題が 11 問しかありません。1 ゲームに 12 問必要です。
出題候補から外した問題:
  - 5 行目 (20260821/3): ... スロット長 5 秒を超えるため出題候補から外しました。
```

12 問揃わなければタイムショックとして成立しない。
中途半端な問題数で遊べてしまうと、データの不備に気づけないため止めている。

### 連番のゼロ埋め

VOICEPEAK は、**同じ接尾語で出力したファイル数**に応じて連番をゼロ埋めする。

| 1 バッチの出力数 | 連番 |
| --- | --- |
| 9 個以下 | `0`〜`8`（ゼロ埋めなし） |
| 10〜99 個 | `00`〜`99`（2 桁） |
| 100 個以上 | `000`〜（3 桁） |

境界は連番の値ではなく**出力数**で決まる。9 個なら 1 桁、10 個なら 2 桁になる。

桁数はバッチ内の `seq` の最大値から自動で判定するため、`questions.csv` には
**整数で書けばよい**（`0` でも `00` でも同じ結果になる）。
表計算ソフトで開くとゼロ埋めは数値として桁落ちするので、CSV 側の表記に
依存しない作りにしている。

## 問題を追加する手順

1. `questions.csv` の `text` 列を表計算ソフトでまとめて選択し、VOICEPEAK に
   貼り付ける（改行がそのままブロック分割になる）
2. `quiz_data/{バッチ名}/` へ連番出力する。**接尾語にはバッチ名（日付）を
   指定する**（12 問なら `00-20260821.wav`〜`11-20260821.wav` のようになる）
3. サーバを起動して、警告やエラーが出ないことを確かめる

CSV の `text` と出力された `.txt` の中身が一致しない場合、どの行がズレて
いるかを表示して起動が止まる。同日に作り直す場合は、同じフォルダへ先頭から
再出力する。
